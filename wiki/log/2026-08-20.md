## [2026-08-20] rebuild | The log moved to one file per day

This wiki kept its entries in a single file per month. A month file is one append point, so two
sessions working the same day collide on it every time — which is the common case, not the rare
one. It happened twice inside a single merge on `malik-llm-wiki` on 2026-08-20, which is what
prompted doing this across the federation rather than one repo at a time.

Entries now live in `wiki/log/YYYY-MM-DD.md`, and `wiki/log/2026-08.md` is a generated **index**
of them. The index row — entry count and operations breakdown — is a projection of the day files
and is produced by `tools/sync_log_index.py`, never hand-typed. Two new CI gates:
`check_log_shape.py` keeps entries out of the month index, and `sync_log_index.py --check`
catches a stale row the same day.

The migration was run by `tools/migrate_log_split.py` in indy-llm-wiki and verified lossless in
both directions: every entry block present before appears exactly once after, byte-for-byte,
checked before the write and again from disk before the month file was cleared. Entry order within
a day is preserved; where a day already had a file, the month file's entries lead and the existing
ones follow.

One thing repaired in passing: this repo carried a stray `2026-08-18.md` day file recording the
house-rules sync, created by a session following indy-llm-wiki's convention in a repo that had not
adopted it. That half-split state is what made the index tooling dangerous here — it is resolved
now, and the stray entry is folded into its day in order.
